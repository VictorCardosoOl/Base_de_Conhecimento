RESPOSTAS E ORIENTACOES SOBRE A ARQUITETURA, DEVOPS E DEPLOY DO PROJETO
Projeto: Base_de_Conhecimento (Monorepo: BaseCore + AuthService)

1. A ESTRUTURA DO PROJETO SEGUE PADROES DEVOPS DO MERCADO?
--------------------------------------------------------------------------------
SIM, com ressalvas positivas! A estrutura atual é conhecida no mercado como MONOREPO 
MICROSERVICES (ou Monorepo Modular):
- BaseCore: Frontend em Next.js (TypeScript).
- AuthService: Microsserviço de Autenticacao/Backend em FastAPI (Python).

Por que isso e comum e aceito no mercado:
- Centraliza o versionamento: mudancas que afetam frontend e auth trafegam no mesmo PR/commit.
- Orquestracao unificada: o arquivo `docker-compose.yml` na raiz sobe todo o ecossistema 
  com um unico comando (`docker compose up -d`).
- Pratica real de mercado: empresas como Uber, Google e Vercel usam monorepos massivos. 
  Nao ha problema em ter duas linguagens/servicos na mesma arvore de diretorios, desde que
  as responsabilidades sejam bem isoladas (e aqui estao, inclusive com Dockerfile proprio para cada).


2. QUAL A MELHOR ESTRATEGIA PARA DEPLOY GRATUITO?
--------------------------------------------------------------------------------
DECISAO ESCOLHIDA: MANTER 1 REPOSITORIO (MONOREPO) E HOSPEDAR EM DOIS SITES
- Frontend (BaseCore) -> Vercel (Gratuito)
- Backend (AuthService) -> Render (Gratuito com Web Service)
- Banco de Dados -> Supabase (PostgreSQL Gerenciado Gratuito, sem expirar)

Como configurar no mesmo repositório:
a) Na Vercel:
   - Conecte o repositório `Base_de_Conhecimento`.
   - Na opção "Root Directory", clique em Edit e aponte para a pasta `BaseCore`.
   - Em Environment Variables, configure as variáveis públicas e URLs de apontamento do backend.
b) No Render:
   - Conecte o mesmo repositório `Base_de_Conhecimento`.
   - Crie um "Web Service" apontando o Root Directory para `AuthService` (ou use o `render.yaml` já existente).
   - Defina as variáveis de ambiente (como `DATABASE_URL` vinda do Supabase).
c) No Supabase:
   - Crie um projeto novo gratuito.
   - Copie a "Connection String" (modo URI) e cole no Render como `DATABASE_URL`.
   - Vantagem: Você mantém tudo versionado em um único commit/PR, sem gerenciar múltiplos repositórios!


3. COMO TRABALHAR E APRENDER SQL NESTE PROJETO (GUIA PRATICO PARA DEVS JUNIOR)
--------------------------------------------------------------------------------
Voce NAO precisa instalar o PostgreSQL manualmente no Windows. O Docker cuida do motor 
do banco de dados! Aqui está o passo a passo de como voce trabalha com SQL no dia a dia:

PASSO 1: Expor a porta do Postgres no Docker (se quiser conectar clientes externos)
No arquivo `AuthService/docker-compose.yml`, o serviço `db` roda internamente. 
Para acessar pelo seu Windows com DBeaver/VS Code, adicione em `services.db`:
```yaml
ports:
  - "5432:5432"
```

PASSO 2: Como acessar o terminal SQL direto pelo Docker (via linha de comando)
Com os containers rodando (`docker compose up -d`), voce pode entrar direto no console interativo do Postgres (`psql`):
```bash
docker compose exec db psql -U authservice -d authservice
```
Comandos uteis do psql para voce aprender:
- `\dt`       -> Lista todas as tabelas criadas no banco.
- `\d users`  -> Mostra a estrutura detalhada de colunas, tipos e chaves da tabela 'users'.
- `SELECT * FROM users;` -> Executa uma consulta SQL pura.
- `\q`        -> Sai do psql.

PASSO 3: Como usar uma ferramenta visual (GUI) para aprender SQL visualizando
Instale uma ferramenta gratuita como DBeaver (https://dbeaver.io/) ou a extensao "Database Client" no VS Code:
- Tipo de conexao: PostgreSQL
- Host: localhost (ou 127.0.0.1)
- Porta: 5432
- Database: authservice
- Username: authservice
- Password: A mesma senha que voce definiu no `AuthService/.env` (`POSTGRES_PASSWORD`)

PASSO 4: Entendendo Migrations (Alembic) vs SQL Puro
No mundo real e nas empresas, quase nunca criamos tabelas dando `CREATE TABLE` manual em producao:
- Usamos ferramentas de Migrations (no Python usamos o Alembic).
- Voce define os Models no Python (`backend/domain/models.py`), e o Alembic gera e aplica as alteracoes no SQL.
- Comando para aplicar migrations:
  `docker compose exec auth-service alembic upgrade head`
- Aprendizado para Dev Junior: Aprenda a ler os arquivos dentro de `AuthService/migrations/versions/`! 
  Eles sao a traducao em codigo Python de comandos SQL DDL (`CREATE TABLE`, `ALTER TABLE`, `ADD COLUMN`).
